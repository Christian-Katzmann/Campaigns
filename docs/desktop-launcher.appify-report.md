Hand-rolled Node.js HTTP server (Node stdlib only — no dependencies, no `package.json` until this run, no bundler, no framework). Single static-frontend bundle in `public/` served by the same Node process. macOS, Node 22, `swiftc` available.

**2. Apps detected:** 1
- **Campaigns** — single Node server on `:4178`, serves `/api/registry`, `/api/document?id=<id>`, plus static files. `node server.mjs`. PORT env-driven by default.

**3. Strategy chosen per app:**
- Campaigns: **A1 native (Swift WKWebView shell)** — the default for any web app where Dock-icon ownership and single-instance activation matter.

**4. Why this is the lowest-effort robust approach:**
No existing Electron/Tauri config, no FSA usage, no Chromium-only API requirements, no cohabiting backend, no static build step. `swiftc` is installed. Strategy A1 native gets a real Dock icon, single-instance activation, fast warm re-launch (verified at 122 ms here), and Cmd+Q vs red-X distinction — none of which the Chrome `--app=` fallback can deliver. Chrome fallback was ruled out solely because it isn't needed.
